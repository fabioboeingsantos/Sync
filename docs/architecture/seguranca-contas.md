# VisionChef — segurança de contas e senhas

Levantamento de segurança atualizado em 26/11/2026 para o piloto controlado. Os controles locais exercitam contas fictícias via PGlite; as 17 migrações (`20261124000100` até `20261126000200`) e as 3 Edge Functions estão publicadas no projeto Supabase `visionchef` (`dqztfllfillntrewutrr`).

## Decisões para o piloto

- **Hash.** O Supabase Auth usa bcrypt com salt para novas senhas. Recomendo mantê-lo como serviço gerenciado do VisionChef. Se Argon2 for obrigatório, será preciso rever a escolha do serviço de autenticação. [Segurança de senhas no Supabase](https://supabase.com/docs/guides/auth/password-security) · [Compatibilidade com hashes importados](https://supabase.com/kb/guides/migrate-from-auth0)
- **Política de senha.** O cadastro, a redefinição e a troca de senha do VisionChef exigem de 8 a 128 caracteres. É possível colar senhas e usar gerenciadores de senhas. Definir a proteção contra senhas comuns ou vazadas e verificar as opções do projeto antes da abertura comercial. [Configuração de senhas no Supabase](https://supabase.com/docs/guides/auth/password-security)
- **Sessão.** A API Node mantém os tokens Supabase dentro de um JWT assinado por `JWT_SECRET_KEY`, enviado em cookie `HttpOnly`, `SameSite=Strict` e `Secure` em HTTPS. A sessão permanece salva automaticamente no dispositivo por **7 dias de inatividade** (`JWT_SESSION_DAYS`, com renovação deslizante automática durante o uso até o teto absoluto de **30 dias** via `JWT_MAX_SESSION_DAYS`), sem salvar senhas no navegador pelo aplicativo — o salvamento opcional da senha é delegado ao cofre nativo do navegador (`PasswordCredential` + `autocomplete`). O navegador conversa somente com endpoints da mesma origem; o backend encaminha o token individual do usuário e preserva as regras RLS e revogação imediata em `/equipe/`. O JWT assinado não é criptografado, portanto o segredo nunca deve ser publicado e a produção precisa usar HTTPS e `JWT_COOKIE_SECURE=true`. [Guia de sessões do Supabase](https://supabase.com/docs/guides/auth/server-side/advanced-guide)

## Evidências e próximos passos

- As migrações ativam RLS em `restaurantes`, `membros_restaurante`, `fornecedores`, `lotes`, `partes_lote`, `saidas_estoque` e `nomes_usuario`. A visão `estoque` usa as permissões de quem consulta (`security_invoker = true`). [Migrações do VisionChef](../../supabase/migrations/)
- A interface chama a API Node em `/api`; a função de login por nome aceita somente chamadas internas assinadas pelo backend. FastAPI e Pydantic são referências do Cesta do Vale. [Cliente do piloto](../../piloto/api.js) · [API Vercel](../../api/handler.js) · [Função de login](../../supabase/functions/login-usuario/handler.js)
- O assistente **Vision** está integrado ao estoque (`/estoque/`) operando localmente no navegador (texto, voz, XML NF-e Fase 1 e OCR local via Tesseract.js), sempre preenchendo sugestões para conferência humana — nunca gravando lotes sozinho nem enviando fotos ou dados a APIs externas de IA.
- Antes de abrir o serviço a restaurantes comerciais externos, separar um projeto Supabase exclusivo para Preview, ensaiar backup/restore e migrar o SMTP para provedor transacional dedicado (SPF, DKIM e DMARC).
